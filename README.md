# 🤖 klyaksa PRO — Telegram Bot & Licensing Server

Автономный Telegram-бот и встроенный HTTP-сервер для продажи, выдачи и валидации пожизненных лицензий **klyaksa PRO**.

Разработан на **чистом Node.js** (v22.5+; проверено с v26) без сторонних npm-зависимостей:
* **База данных**: PostgreSQL из `DATABASE_URL` (Render), с локальным SQLite fallback для разработки и миграцией без потери данных.
* **Сетевой стек**: нативный `fetch` (Telegram Bot API) и встроенный HTTP-сервер (`node:http`) на порту **3782**.
* **Безопасность**: криптостойкая генерация ключей (`node:crypto`), привязка ключа к аппаратному ID (`HWID`) компьютера, защита от повторных активаций.

## 🚀 Быстрый старт за 2 минуты

### Шаг 1. Получение токена бота
1. Откройте в Telegram официального бота [@BotFather](https://t.me/BotFather).
2. Отправьте команду `/newbot`.
3. Задайте имя (например, `klyaksa PRO Store`) и юзернейм (например, `klyaksa_pro_bot`).
4. Скопируйте полученный токен (вида `123456789:ABCdefGHIjklMNOpqrsTUVwxyz`).

### Шаг 2. Как узнать свой Telegram ID (для админки)
1. Откройте бота [@userinfobot](https://t.me/userinfobot) или [@raw_data_bot](https://t.me/raw_data_bot).
2. Скопируйте числовой `Id` (например, `123456789`).

### Шаг 3. Настройка `config.json`
Откройте файл `config.json` и укажите ваши данные. Поле `bot_token` оставьте пустым: токен хранится в пользовательской переменной окружения `KLYAKSA_BOT_TOKEN`. Старое поле `bot_token` поддерживается для обратной совместимости, но переменная окружения имеет приоритет:

```json
{
  "bot_token": "",
  "admin_id": 123456789,
  "server_port": 3782,
  "plans": {
    "lifetime": {
      "name": "klyaksa PRO Lifetime",
      "price_rub": 269,
      "price_stars": 249,
      "description": "Пожизненный доступ ко всем темам, стилям глаз и будущим PRO-обновлениям."
    }
  },
  "payment_details": {
    "bank_name": "Т-Банк (Тинькофф) / Сбербанк",
    "phone_or_card": "+7 (999) 123-45-67",
    "recipient_name": "Иван И.",
    "comment_instruction": "В комментарии к переводу укажите ваш никнейм в Telegram"
  },
  "app_scheme": "klyaksa",
  "support_contact": "@your_username"
}
```

### Шаг 4. Сохранение токена и запуск бота
Точное имя пользовательской переменной окружения: `KLYAKSA_BOT_TOKEN`.

В PowerShell задайте её один раз для текущего пользователя (значение не попадёт в файл проекта):

```powershell
[Environment]::SetEnvironmentVariable('KLYAKSA_BOT_TOKEN', 'ВАШ_ТОКЕН_ОТ_BOTFATHER', 'User')
```

Закройте и заново откройте консоль, затем из каталога проекта запустите `node bot.js` или дважды кликните `start_bot.bat`. Для разовой проверки без сохранения переменной используйте:

```powershell
$env:KLYAKSA_BOT_TOKEN = 'ВАШ_ТОКЕН_ОТ_BOTFATHER'
node bot.js
```

Токен не сохраняйте в `config.json`; при пустой переменной бот запускает встроенный HTTP-сервер и остаётся в режиме ожидания токена.

## 💳 Способы оплаты и сценарии работы

### 1. Telegram Stars (249 ⭐️)
* Пользователь нажимает **`⭐️ Оплатить Stars`**.
* Бот отправляет инвойс Telegram Stars (`XTR`).
* Списание происходит внутри Telegram в 1 клик.
* Сразу после оплаты бот генерирует лицензионный ключ формата `KLYA-PRO-XXXX-XXXX`, привязывает к покупателю и присылает сообщение с кнопкой **«🚀 Активировать в 1 клик»**.
* Администратор получает моментальное уведомление о покупке.

### 2. СБП / Банковская карта (269 ₽)
* Пользователь нажимает **`💳 Оплатить через СБП`**.
* Бот выводит реквизиты (банк, телефон/карту, имя получателя) и переводит чат в режим ожидания чека.
* Покупатель переводит 269 ₽ и отправляет скриншот или PDF квитанции в чат с ботом.
* Бот пересылает чек владельцу (`admin_id`) с двумя интерактивными кнопками:
  * **`[ ✅ Подтвердить и выдать ключ ]`** — генерирует ключ, фиксирует оплату и высылает покупателю ключ.
  * **`[ ❌ Отклонить ]`** — отклоняет заявку и уведомляет покупателя.

### 3. Кнопка «🔑 Мой ключ / Проверить»
* Покупатель в любой момент может посмотреть все приобретённые им лицензии, статус активации и HWID компьютера.

## 👑 Панель администратора (`/admin`)

Доступна только пользователю с ID, указанным в `admin_id`.

Команда `/admin` открывает дашборд:
* **📊 Статистика**: общее число ключей, активированных на ПК, доступных к продаже, суммарная выручка в рублях и Stars.
* **`[ ➕ Выпустить 1 ключ ]`**: генерация единичного промо-ключа для ручной выдачи.
* **`[ 📦 Выпустить 5 ключей ]`**: генерация пачки из 5 ключей.
* **`[ 📋 Свободные ключи ]`**: просмотр последних неактивированных ключей в базе.
* **`[ ⏳ Ожидающие чеки ]`**: список заказов по СБП, ожидающих ручной проверки.
* **💻 Уведомления об активации**: когда пользователь вводит ключ на своём компьютере, бот присылает админу отчёт с HWID машины и точным временем.

## 💻 Консольная генерация ключей

Если нужно быстро создать ключи без Telegram:
```bash
# Создать 1 ключ:
node generate_key.js

# Создать 5 или 10 ключей:
node generate_key.js 5
```
Ключи сохраняются в выбранной базе со статусом `available`.

### PostgreSQL Render и миграция SQLite

Установите зависимости командой `npm ci`. Если задана переменная `DATABASE_URL`, бот и HTTP API используют PostgreSQL; без неё сохраняется локальный SQLite fallback. Render обычно предоставляет `DATABASE_URL` автоматически.

Для переноса существующих данных из `database.sqlite` задайте только `DATABASE_URL` в окружении и выполните:

```powershell
$env:DATABASE_URL = 'postgresql://...'
npm run migrate
```

Миграция создаёт таблицы и индексы, выполняется одной транзакцией, повторный запуск идемпотентен по ключам лицензий и ID заказов, а после записи проверяет количество строк. Скрипт не выводит ключи, токены или содержимое строк. Перед миграцией сделайте резервную копию SQLite. Для локальной проверки без подключения к БД используйте `npm run check` и `npm test`.

## 🌐 HTTP API для приложения klyaksa (порт 3782)

Встроенный HTTP-сервер обеспечивает интеграцию с десктопным приложением. По умолчанию он слушает только `127.0.0.1`; при необходимости адрес можно задать параметром `server_host` в `config.json`.

Для POST-запросов действуют отдельные лимиты по IP соединения: активация — 10 в минуту, проверка — 60 в минуту, обращения — 5 за 10 минут. При превышении возвращается HTTP 429 с `Retry-After`. Максимальное тело — 64 KiB для активации и проверки, 10 MiB для обращения со скриншотом; при превышении возвращается HTTP 413. Счётчики хранятся в памяти каждого процесса и сбрасываются при перезапуске. Заголовки прокси не используются: за обратным прокси все клиенты будут иметь общий лимит по его адресу; для такой схемы нужна дополнительная настройка защиты на прокси.

### 1. `POST /api/activate`
Активация ключа при первом вводе или повторном открытии:
* **Тело запроса (JSON)**:
  ```json
  {
    "key": "KLYA-PRO-XXXX-XXXX",
    "hwid": "KLYA-HWID-XXXX-XXXX"
  }
  ```
* **Ответ при успехе (HTTP 200)**:
  ```json
  {
    "success": true,
    "tier": "ProLifetime",
    "message": "Лицензия klyaksa Pro Lifetime успешно активирована навсегда!"
  }
  ```
* **Ответ при попытке ввода чужого ключа на втором ПК (HTTP 200)**:
  ```json
  {
    "success": false,
    "error": "Этот ключ уже активирован на другом устройстве! Ключ klyaksa PRO является единоразовым."
  }
  ```

### 2. `POST /api/verify`
Проверка валидности ключа без смены статуса.

### 3. `GET /api/status`
Healthcheck сервера.

## 🔗 Активация в 1 клик (`klyaksa://`)

Бот отправляет ссылки формата:
```
klyaksa://activate?key=KLYA-PRO-XXXX-XXXX
```
При нажатии на такую ссылку Windows автоматически передаёт ключ в приложение klyaksa, которое регистрирует данный протокол в реестре при первом запуске.
